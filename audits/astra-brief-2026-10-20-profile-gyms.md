## What to look at, in priority order
1. **013 (`supabase/013_profile_fields.sql`), applied to prod.** New columns on `profiles` with check constraints and the column-level `grant update` from 006 extended. Confirm (a) a user still cannot update `id`, `email`, `created_at`, `is_*` of another row; (b) the `prs` and `socials` jsonb constraints hold against hand-built payloads (array of 4, nested objects, 10 KB strings) sent straight to PostgREST with a user JWT; (c) `profiles_avatar_own` (avatar_path must start with the caller's uid + '/') cannot be bypassed with a path like `<other-uid>/../<my-uid>/x`.
2. **Avatars bucket policies (same file).** Public read; insert/update/delete only where `(storage.foldername(name))[1] = auth.uid()::text`. Try: upload to another user's folder, upload to the bucket root (`avatar.png`, no folder), a 2.1 MB file, a `image/svg+xml` file, a `.png` with `image/jpeg` content type. Client side, `lib/auth/avatar.ts` names files `<uid>/avatar-<ts>.<ext>` and removes the previous object after upload; check that a failed removal cannot leave `avatar_path` pointing at a deleted object (order is upload, then profile update, then remove old).
3. **Sanitiser `cleanProfilePatch` (`lib/auth/profile.ts`).** It is the only path from the Account form to `profiles.update`. `cleanHandle` turns pasted links into handles; `cleanWebsite` forces http(s) and drops anything else. Try `javascript:`, `data:`, protocol-relative `//evil`, unicode look-alikes, a 400-char Instagram URL, handles with dots (must survive: `kurt.lifts`), and confirm `socialUrl` output is safe to put in an `href` (it is not rendered anywhere public yet; this is ahead of the athlete pages).
4. **Account page (`components/website/AccountClient.tsx`).** The About-you block edits one object; `dirty` compares the cleaned patch, so a trailing space must not enable Save and an empty PR row must not count. Photo upload saves immediately, outside the Save button: confirm the busy states cannot overlap (upload while Save is in flight, Remove during upload). Also the hydration warning on `/website/account` when signed in (server renders the signed-out card, client swaps): cosmetic or does it ever lose form state?
5. **Gym Directory zip + radius (`lib/geo/geo.ts`, `lib/geo/zcta.ts`, `app/api/zip/[zip]/route.ts`, `components/website/GymsBrowser.tsx`, `lib/website/filters.ts`).** `/api/zip/<zip>` is `force-static` with a dynamic segment; confirm Next 16 serves it correctly on Vercel for an arbitrary zip (not just build-time ones), that a non-numeric segment 404s and never 500s, and that the 760 KB JSON stays out of every client bundle (check the browser network tab on `/gyms`). Filter logic: gyms without coordinates drop out when a zip is set; results sort by distance; unknown zip shows the red note and leaves the list unfiltered (deliberate; say if you think it should empty the list instead).
6. **Header (`components/website/WebsiteAccountChip.tsx`, `WebsiteThemeControls.tsx`).** Signed-out chip now renders nothing; day/night button is icon-only with `aria-label`. Keyboard and screen-reader pass on the header, and confirm the Account tab is reachable as the only sign-in entry from every public page including `/m/<slug>` and `/join`.
7. **Fixtures (`lib/website/fixtures.ts`).** The Power Plant gym fixture is now the fictional Keystone Forge Strength (Media, PA). Grep for anything still naming the real gym outside the known exceptions below.
8. **Copy pass.** Gym Directory intro, equipment list labels (`lib/website/gymEquipment.ts`), About-you labels and the trainer note. Kurt's rule stands: say what it does for the person, no colon-then-fragments, no "not X, it is Y".
