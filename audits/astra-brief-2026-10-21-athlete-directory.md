## What to look at
1. **The view is the whole boundary.** As anon and as your (private) account: `zt_public_profiles` returns only `slate_staging`; `select=email` is 42703; the base `profiles` table still returns only your own row. Then flip your own `is_public` on through REST with `username` null (expect the check constraint), and try to write `username` directly through PATCH on `profiles` (expect no column grant). Confirm `username_holds` is unreadable and unwritable from both roles.
2. **`zt_set_username` edge cases.** Mixed case and a leading `@` (should store lowercase), 2 and 31 chars, a hyphen, every reserved word you can think of that is not in the list (routes we have: `/athletes`, `/shows`, `/gyms`, `/join`, `/scorer`, `/demo`, `/legal`, `/website`, `/promoter`, `/m`, `/register`, `/api`), a name another account holds, the hold: set a name on account A, change it, then try to take the old name from account B (expect the 30-day message), then take it back on A (expect success). Concurrency: two accounts racing for the same free name should end with one 23505 mapped to "taken", never two rows.
3. **Clearing.** Clear the username while public: is_public must drop to false in the same statement and the page must 404 within the 60 s revalidate window. Check nothing else on the profile changed.
4. **Pages.** `/athletes/<name>` for a private user is a 404, not an empty page. Usernames with `%40`, uppercase, trailing slash. The avatar URL is built client-side from `avatar_path`; try to get a path with `..` or a leading `/` into a row (constraint `profiles_avatar_own` from 013 should stop it) and confirm the page renders no image rather than a broken URL. Socials render through `socialUrl`, so a stored `website` that is not http(s) must not link.
5. **Account page.** The username form saves on its own, the visibility switch saves on its own, the big Save button covers the rest; make sure an unsaved edit above is not lost or silently saved by either. Error messages from the RPC show as-is; check they read right.
6. **Privacy copy.** The section says "Your email never shows." Hold it to that. The profile page footer says everything was entered by the person; check it is true (badges come from their own role flags).
7. **Known, not claimed:** shows on the profile (s7 item 4) and promoter/gym cross-links (item 5) are not built; the `stateFromLocation` guess is a filter convenience, not data; the trainer filter is not yet `/trainers`.
