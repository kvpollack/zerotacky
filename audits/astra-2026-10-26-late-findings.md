# Astra late-release audit, 2026-10-26

**Fix three SHIP findings before the next release.** The audit also found one DAY-OF issue and four LATER items. Migration 024 blocks anonymous publishing and signed-in nonmembers on the tested existing slug. It does not make all roster writes account-only. The shared theme preference works across pages, but saved light themes trigger a hydration failure on the root and Join pages.

## Findings

SHIP means fix before the next release. DAY-OF means volunteers need a workaround or a warning until fixed. LATER covers bounded behavior or usability issues that did not block the tested flow. All eight findings are open for disposition. No fixes were made by this audit.

## Coverage against the brief

### 1. Migration 024 and remaining write paths

- **Anonymous publishing is blocked.** The no-key signature, a null `p_key` argument, and a dummy string key each returned 401 on staging. The old table returned 404 from PostgREST's schema cache.
- **An authenticated nonmember cannot publish into the fixture's slug.** A new UUID plus Iron Harbor's existing slug returned 403, `this meet belongs to another promoter`, for all three payload shapes. The account's lack of membership was separately verified. The member check precedes writes in the SQL.
- **Overload resolution worked for the tested payloads.** For the authorized fixture owner, all three forms reached the same deliberately invalid event-array error, code 22023. These requests were designed to roll back, so no valid live publish was committed during this audit. Dispatch and authorization were verified. Successful full publication was not exercised.
- **Most tested anonymous table updates were blocked.** Anonymous updates to meets were denied. Divisions/events updates matched no writable rows, with or without the join code. Athlete updates without the join code also matched no rows. LT-01 is the confirmed exception. Negative nonmember table probes did not write rows.
- **Ownerless recovery was source-reviewed only.** A remaining member passes the check and becomes owner through the upsert. A stranger is refused before writes. The refusal should retain the support/recovery instruction: `zt_transfer_ownership` requires the current owner, so directing an orphaned meet's stranger to that RPC would not solve recovery. No account was deleted and no ownerless fixture was created.
- **Grant-based scores/live-state remain intentional.** Source preserves the 011 grant path. An actual new staging grant and score write were not needed for this audit and were not performed.

### 2. Client retirement and legacy links

- The app's publish payload omits `p_key`. A local controller probe converted a legacy key-auth link to account auth, set `userId`, and made the next sign-out pause the link. A subsequent tick made zero requests. The matching unit test also passed.
- An accountless legacy link with a valid mock grant flushed a synthetic score in the local controller test. This verifies client behavior. Live SQL grant behavior was not re-tested.
- The staging scorer removed the saved-key sentinel on mount, disabled Publish update while signed out, and displayed the sign-in action. Runtime source references to the saved-key constant are its declaration and cleanup import/removal. The remaining functional key dependency is the restore tool, LT-02. Historical notes and old SQL migrations still mention keys.
- The browser legacy-link check used an isolated local cache and blocked all non-read network requests. It did not publish, change the remote roster, or update the live cursor. LT-04 and LT-08 cover the remaining client issues.

### 3. Shared themes and scoreboard layouts

- Join selecting Warm Pavement persisted to the scorer on the same isolated phone. Selecting Power Plant Volt in the scorer persisted back to Join. No cross-tab synchronization claim is made.
- A board URL with `?theme=daylight` overrode a saved Volt preference. Day/Night switched relative to the displayed light theme to Steel and persisted the result. Picking Volt afterward dropped the in-memory override and displayed Volt.
- At 375 px, the board document width was 375 and the title/control header was 347 px wide. The palette was inside the viewport at x=12 with width 351. At 1920x1080 with `?layout=tv`, the palette was 288 px wide at x=1334.16, y=76, with bottom 832. Its height is capped and it scrolls. See [TV capture](late-2026-10-26/board-palette-1920.png).
- The Completed/Final dry-run board still displayed Final results and no Up Now rows. The tested board had no hydration error with a saved Daylight theme. Root and Join failed as described in LT-03.

### 4. Skip link and phone header

- The first keyboard Tab reached Skip to content. Enter moved focus to `main#zt-main`, and the next Tab reached the first content Sign in action rather than restarting the header.
- In Daylight, the skip link became a visible 140.80x32 px blue/white control with an outline. Removing the main element's outline did not prevent focus transfer or the tested tab sequence. Actual screen-reader announcements were not tested.
- The authenticated header measured 117 px before and after releasing the held profile response. Join kept the same x-position and width. The compact account chip appeared with accessible label `Account: Slate Staging` without adding a row.
- The settled signed-out header also measured 117 px. An earlier zero-size pre-settle sample is retained in raw evidence but is not used as proof of a layout jump. The signed-out screenshot was captured during theme recovery and is not used for a contrast conclusion.
- Account remains initially off-screen, LT-07. Focusing it scrolls it into view, so keyboard access remains functional.

### 5. Timestamps and directions

- Iron Harbor's actual six-digit fractional Supabase timestamp `2026-10-26T19:33:18.161245+00:00` rendered as `Oct 26, 2026, 3:33 PM` in the America/New_York browser zone. The `<time>` element retained the full ISO value. Separate `+00:00` and `Z` microsecond samples parsed to the same millisecond in Chrome and Bun.
- **Safari is not certified.** No Safari or WebKit engine was available in the installed browser set. The date-only pre-mount rendering is source-reviewed, and the local-time result was verified in Chrome. No assertion is made that all Safari versions accept the microsecond form. A future compatibility test should include WebKit or normalize the fraction to milliseconds before parsing.
- The live snapshot's source is the latest received result's `server_at` when any result exists, otherwise the meet's `updated_at`. It marks the last score update rather than the time the page fetched its snapshot. The new formatter preserves this existing meaning. Consider separating listing-update and score-update labels if both are needed, but no new timestamp regression was established here.
- Iron Harbor's Directions URL encoded the facility and address fields on file and used `_blank` with `noopener noreferrer`. No geocoding accuracy was assumed and no Google Maps result was opened. Missing data and fictional venues are covered by LT-05/06.
- The unlisted dry-run correctly did not render a show-directory page. Its direct scoreboard was used for the Completed variant instead.
