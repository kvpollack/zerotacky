# Astra scorer-polish audit, 2026-10-26

**Fix six SHIP findings before the next release.** There is also one DAY-OF recovery issue and two LATER items. The two-phone collar update works, including explicit zero, and the revised pit-crew card fits at 375 px. The remaining problems are specific to loading-mode consistency, scratch scoring, editor navigation, and derived history.

## Findings

SHIP means fix before the next release. DAY-OF means a documented workaround is available, but the meet crew needs to know it. LATER covers documentation and input hardening that did not break the supported UI path tested here. All nine findings are open for disposition. This audit does not implement fixes.

| ID | Severity | Finding | Suggested fix |
|---|---|---|---|
| PS-01 | SHIP | **The event form offers collars for a four-post total-weight load, but the engine ignores them.** The form shows and saves `collarWeightPerPair` for every 4-point event. With target 500, tare 100, and event collars 10, the engine returns 100 per post and `collarWeightApplied: 0`. A promoter is told the entered collar weight will be deducted, but it has no effect in this mode. | Preserve the existing collar-free yoke rule by hiding the field and saving 0 for `loadingPoints=4, weightEntryMode=total`. Keep it for two sleeves and four-sleeve per-hand loads. If collars on posts are intended to be supported, define the pair count and implement that arithmetic before exposing the field. Add tests for switching between both 4-point modes. |
| PS-02 | SHIP | **A zero-score withdrawn athlete can still inflate the points field.** `resultHasScore()` treats any positive time as a score without consulting the event. In a 60-second time-or-distance event, a withdrawn athlete with time 61 and distance 0 is correctly scored as zero but still counts toward N. Two finishers receive 3 and 2 points instead of 2 and 1. The judge input permits this value. | Make field eligibility use the event's actual nonzero-score rules, with event definitions available to the predicate. Cover over-cap zero-distance and zero-implement results, DNS, and valid partial results. Do not infer a score from a numeric field that the event does not use. |
| PS-03 | SHIP | **The no-score scratch rule does not carry into overall placings.** In a division with one finisher, one active zero, and one withdrawn athlete with no result, the scratch is correctly event-place 3 with 0 points. Both overall tiebreak modes then put the scratch and active zero at tied 2nd. `calculateDivisionStandings()` still ranks every roster row together. | Apply the same field membership to overall ranking. Rank eligible athletes first and display excluded scratches below the field at N+1 with 0 points, without marking an active athlete tied with a scratch. Preserve earned points and placings for athletes who withdraw after scoring. Add tests for both overall tiebreak modes and the website adapter. |
| PS-04 | SHIP | **Go to Listing bypasses the event-form tab lock.** Edit a Listing field without saving, switch to Events, and open Add Event. The sticky bar's Go to Listing button calls `setActiveTab()` directly. Staging switches to Listing and hides the still-open event form despite the disabled tabs. This is recoverable through Go to Events or Discard draft, so it is not a permanent trap. | Route all tab-changing controls through `requestTab()`, including the sticky-bar shortcuts. Add a browser test with a dirty Listing and an open event draft. Verify refusal leaves Events visible and focuses the warning. |
| PS-05 | SHIP | **The new sticky-bar action combination clips Save Changes on a 375 px phone.** With a builder edit plus an open event draft, Discard draft, Discard, and Save Changes stay on one nonwrapping row. Save Changes ends at x=392.34 in a 375 px viewport. The document width remains 375, so page-overflow checks alone miss it. | Make the inner action container wrap or use a phone-width grid, with buttons constrained inside the bar. Test builder-only, draft-only, Listing-plus-draft, and all-dirty combinations. Assert every action's bounding rectangle fits the viewport and remains keyboard reachable. |
| PS-06 | DAY-OF | **A reopened meet does not regain Resume on a phone that cached Completed.** `readResume()` returns null, and `RootLanding` immediately returns before refreshing the status. A browser seeded with cached Completed against the real upcoming staging fixture made zero status requests and kept the card hidden. This models a stale cache without reopening a server fixture. The helper's unit test passes because it calls the refresh function directly. | Refresh whenever a valid linked meet exists, even if the initial card is hidden. After a successful refresh, recalculate `readResume()` so the card can appear as well as disappear. Add a component-level reopened-meet test. Until fixed, open `/scorer` directly or use Join a meet after a promoter reopens the meet. |
| PS-07 | SHIP | **Show History can display an impossible placing, such as 3rd of 2.** Its placing comes from engine standings, which retain earned results after a mid-meet withdrawal, but `fieldSize` removes every withdrawn athlete. In the local fixture, a scored withdrawn athlete places ahead of two active athletes. The history entry for the last active athlete formats as `3rd of 2`. | Use the same scoring-field definition for the displayed denominator and placing. Keep mid-meet withdrawals in that field and exclude pre-score scratches consistently. Add a history regression with a scored withdrawal ahead of an active athlete. |
| PS-08 | LATER | **First-show guide screenshots still teach the old tab order.** The guide text now says Events is tab 3 and Stations tab 4. The referenced `06-events.png` visibly says Stations 3, Events 4, Athletes 5, Listing 6, and Registrations 7. Its Events heading also says 4. The inspected alt text has no stale tab number. | Recapture the affected promoter-editor guide images using the new order and collar form. Check the images themselves as well as their alt text. |
| PS-09 | LATER | **Incoming JSON can retain a string collar override and silently fall back to the meet value.** A local `rowToEvent()` probe with `config.collarWeightPerPair: "10"` preserves the string. The engine uses meet collars 5 instead of event collars 10. Normal form saves were numeric, so this is input hardening rather than a demonstrated bad UI save. The shared sanitizer also preserves a nonzero collar on 0/1-point events, although EventForm saves 0 and the engine ignores it. | Normalize finite, nonnegative collar values at the shared import/sync boundary, preserving absent values for the legacy fallback. Make unsupported loading modes consistently store 0. Add string/null/nonfinite and 0/1-point regression cases. |
